1. 3分钟快速上手

步骤1：点击“添加文件”，上传一张或多张标准照片。
步骤2：勾选“人脸”（可选叠加：全景/聚焦/文字）。
步骤3：点击“开始搜索”。
步骤4：使用“首批/上批/下批/末批”翻页，结合排序快速定位。
步骤5：对命中结果执行“标准照片 / GPS中心 / 原图 / 重命名 / 删除 / 下载”。
步骤6：若要浏览整个照片库，可直接勾选“文字 + 全类型文件”后点击“开始搜索”（可不上传标准照片）。
步骤7：在“排序”下拉框切换不同排序方式，可快速查看不同排序效果。
首次建议：先用“人脸 + 默认设置”跑一轮；需要全库浏览时，使用“文字 + 全类型文件”。

3. 上传标准照片（核心入口）

3.1 操作方法

  • 点击“添加文件”，可多选图片。
  • 已添加的标准照片可在列表中查看、勾选、删除。
  • 结果卡片中的“标准照片”按钮，也可把命中图加入标准池。

3.2 清理按钮

  • 删除选中：只删勾选项。
  • 清空：清空当前标准照片列表。
  • 清空所有：清空标准照片 + 上传池 + GPS中心联动状态。
  • 刷新：重新读取标准照片列表。

3.3 使用建议

  • 优先选“脸部清晰、角度正常、光线稳定”的照片。
  • 同一人物可上传多张，提高检索稳健性。
  • 多人检索时，建议按人物分批搜索，避免条件过杂。
若“人脸 AND”无结果，可先切到 OR，再逐步收紧条件。

4. 搜索要素与参数说明

模块参数作用建议
人脸 OR / AND；至少匹配；预裁剪 主检索维度，决定人脸召回与精度 先 OR 后 AND；至少匹配留空可自动
全景 勾选开关 按整图语义匹配（风景/室内/街景等） 与人脸叠加时可显著减少误命中
聚焦 中心/垂直/十字/横向（可多选） 对图像关注区域进行限制 主体常居中时优先“中心”
文字 关键词；AND/OR；全类型文件 按文件名/目录关键词过滤 全类型文件适合全库排序浏览
要素逻辑 AND / OR 决定“人脸/全景/聚焦/文字”之间的组合关系 精准检索用 AND；宽松召回用 OR

5. 开始搜索与结果浏览

5.1 开始搜索

  • 点击“开始搜索”后，系统会返回当前批次结果。
  • 默认每批 55 张，底部会显示“第 x/y 批 ｜ 共 n 条”。

5.2 翻页

  • 首批：跳到第一页
  • 上批：上一页
  • 下批：下一页
  • 末批：最后一页

5.3 调试信息怎么看

  • “查看调试详情”可看到各要素命中数量和组合后返回数。
  • 当命中明显偏少，优先查看：
    • 人脸逻辑是否过严（AND + 至少匹配过大）
    • 文字关键词是否过窄
    • 日期/GPS是否限制过小
建议养成“先宽后严”的检索习惯：先召回，再逐步收紧。

6. 搜索结果排序（11种）

当前支持：时间新→旧、时间旧→新、相似度高→低、相似度低→高、脸数多→少、脸数少→多、限定脸数、距参考点近→远、距参考点远→近、文件名A→Z、文件名Z→A。

6.1 限定脸数（重点）

  • 选择“限定脸数”后，会出现脸数输入框。
  • 输入范围为 0..n，n 为当前搜索结果中的最大脸数。
  • 输入 0 表示只看“无脸”的照片。
  • 该逻辑基于整次搜索结果，不是只针对当前页。

7. 搜索结果卡片操作

按钮作用说明
原图打开原始文件用于核验细节与导出前复查
重命名修改文件名物理文件 + 数据库同步更新；扫描中禁用
标准照片加入标准池便于下一轮组合检索
GPS中心设置中心点用于后续半径查询或叠加查询
删除移入回收目录移动到 pre_deleted 并清理数据库关联
勾选批量操作与“下载选中 / 删除”联动
“删除”不是立即粉碎：会先移动到项目回收目录，便于审计与回溯。

8. GPS中心与搜索日期

8.1 GPS中心使用流程

1）先在结果卡片点击“GPS中心”。
2）在“GPS 半径查询”输入公里数。
3）选择“按GPS半径查询”或“按GPS半径叠加要素查询”。

8.2 日期过滤

  • 可设置起始/结束日期。
  • 支持快捷按钮：全部日期 / 前1月 / 前5年。
  • 与任意搜索要素可叠加。

9. 手机端专用说明

底部固定条

固定“首批/上批/下批/末批”，并整合排序选择，适合单手操作。

设置快速按钮

底部“⚙ 设置”为 sticky 按钮，展开可自动定位系统设置，关闭后回页顶。

图片浏览

手机端建议使用系统浏览器并定期强制刷新，避免缓存导致样式不同步。

11. 扫描与时间修复

11.1 什么时候用扫描

  • 增量扫描：日常新增/移动/删除后使用（推荐）。
  • 断点扫描：上次中断后继续。
  • 全扫描：仅在重大修复、索引重建时使用。

11.2 时间修复规则

  1. 优先读取 EXIF 时间；
  2. 没有 EXIF 时，根据路径“年/月”推断；
  3. 再不行回退到文件 mtime。

修复任务会显示 x/n 进度。

扫描中禁止重命名与部分高风险动作，建议先结束扫描再进行管理操作。

12. 索引体检与压实（重要）

1）先体检（dry-run）：查看当前索引健康，不改写文件。
2）确认备份：建议备份数据库 + 索引 + 配置。
3）再压实：可选压实人脸、压实视觉、一键全压实。
4）压实时停扫：避免与扫描并发，防止索引抖动。
正式压实前会要求输入确认短语：我已备份并确认压实。

14. 常见问题（FAQ）

Q1：上传标准图后搜索不到人脸？

A：先检查标准图是否清晰；将人脸逻辑改为 OR；减少附加条件后再逐步收紧。

Q2：明明有新照片，为什么没显示？

A：需要先跑一次增量扫描，索引和数据库才会同步新增文件。

Q3：时间显示异常（例如偏到 2026）怎么办？

A：在系统设置执行“时间修复”，并选择目标目录。

Q4：删除后为什么列表变化很大？

A：删除会影响当前搜索结果集合，建议删除后重新执行一次搜索。

Q5：排序里的“限定脸数”为何看不到输入框？

A：只有当排序模式切换到“限定脸数”时，输入框才会显示。

17. 本系统使用的核心技术

17.1 技术架构图（示意）

检索核心链路：前端输入 -> FastAPI 组合检索 -> MySQL 过滤/回填 -> FAISS 相似检索 -> 结果分页与排序。

17.2 技术栈清单

FastAPI Uvicorn MySQL PyMySQL InsightFace OpenCLIP FAISS Pillow / pillow-heif HTML / CSS / JavaScript
